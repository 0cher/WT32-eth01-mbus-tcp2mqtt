# WT32 M-Bus → MQTT Шлюз

Прошивка для платы **WT32-ETH01** (ESP32 + Ethernet), которая работает как **M-Bus TCP/IP в MQTT шлюз**.

Позволяет считывать данные с M-Bus счётчиков (тепло, вода, газ, электричество) через TCP-подключённый M-Bus мастер (например **PW50 от Relay GmbH**, iMega) и публиковать декодированную телеметрию в MQTT брокер по TLS.

> **⚠️ Важно:** Прошивка протестирована только со следующим оборудованием:
> - **M-Bus мастер:** PW50 (Relay GmbH) — TCP/IP M-Bus шлюз
> - **MQTT брокер:** EMQX (включая TLS-подключение)
> - **Maddalena Water (MAD)** — счётчики воды
> - **Landis Heat (LUG)** — теплосчётчики
>
> **Количество Slave-устройств:** максимальное количество одновременно опрашиваемых M-Bus устройств пока не определено, так как тестирование проводилось не более чем с 3 счётчиками на шине.
>
> Работа с другими производителями не гарантируется, но протокол M-Bus является стандартным, поэтому большинство счётчиков должны быть совместимы.

---

## 🔑 Важно: Серийный номер (SN) — ключевой идентификатор

Серийный номер устройства используется в трёх местах:

| Назначение | Значение |
|------------|----------|
| **MQTT Client ID** | = SN |
| **MQTT Username** | = SN |
| **Пароль от веб-интерфейса** | = SN (по умолчанию) |

По умолчанию пароль от веб-интерфейса равен серийному номеру, который был записан в NVS при первой загрузке:

- Если вы не меняли SN — пароль = `DEVICE_SN` из прошивки (значение в `DeviceConfig.h`)
- Если меняли через `PROVISIONSN` — пароль = новый SN

Изменить пароль можно на странице **Web Access** веб-интерфейса.

## ⚡ Режимы восстановления (важно!)

Прошивка имеет **два независимых режима восстановления**, которые могут потребоваться, если вы забыли пароль от веб-интерфейса или хотите полностью сбросить настройки:

### 1. UART режим — сброс через Serial (dev-профиль)

При загрузке в **dev-профиле** плата ожидает **5 секунд** команду через Serial:

| Команда | Действие |
|---------|----------|
| `RESETWEB` | Сбросить учётные данные веб-интерфейса на `admin` / серийный номер |
| `PROVISIONSN` | Перезаписать серийный номер в NVS из сборки `DEVICE_SN` |

### 2. GPIO режим — аппаратный сброс NVS (работает в обоих профилях)

Работает в **dev** и **prod** профилях. Используйте если UART-режим недоступен:
- Замкните **GPIO12 на GND** при подаче питания
- NVS будет **полностью стёрта** (все настройки сброшены)
- **Удалите перемычку** перед следующей перезагрузкой

## Возможности

- **M-Bus протокол** — сканирование первичных адресов (1–250), поиск по вторичному адресу с фильтрацией диапазона, чтение телеметрии в реальном времени с полным парсингом VIF/VIFE полей данных
- **MQTT поверх TLS** — подключение к любому MQTT 3.1.1 брокеру с опциональным пользовательским CA-сертификатом (загружается через веб-интерфейс)
- **OTA обновления** — прошивка поддерживает обновление по воздуху через веб-интерфейс (страница Firmware Update)
- **Веб-интерфейс администратора** — полнофункциональный браузерный интерфейс с Basic Auth:
  - Статус устройства (Ethernet, MQTT, синхронизация времени, память)
  - Настройки MQTT брокера (хост, порт, учётные данные, TLS, топики)
  - Сетевые настройки (DHCP / статический IP, DNS)
  - Настройки M-Bus шлюза (хост, порт)
  - Управление M-Bus устройствами: сканирование, сохранение, удаление
  - Просмотр телеметрии в реальном времени с декодированными полями
  - Настройка синхронизации времени (SNTP) и часового пояса
  - Обновление прошивки по OTA
- **Автообновление снапшотов** — периодически опрашивает все сохранённые M-Bus устройства, кэширует значения и публикует JSON телеметрию + логи в MQTT
- **Health Watchdog** — мониторинг Ethernet, MQTT и интернет-соединения; автоматическая перезагрузка при устойчивых сбоях

## Быстрый старт

### Требования

- [PlatformIO](https://platformio.org/) (расширение VS Code или CLI)
- M-Bus TCP шлюз (например PW50, iMega) в вашей сети
- MQTT 3.1.1 брокер (например [EMQX](https://www.emqx.io/), [Mosquitto](https://mosquitto.org/), [HiveMQ Cloud](https://www.hivemq.com/mqtt-cloud-broker/))

### Настройка перед первой прошивкой

Перед первой загрузкой укажите в файлах конфигурации минимальные параметры, чтобы плата могла подключиться к вашей сети. Вы также можете настроить их позже через веб-интерфейс.

1. **Клонируйте репозиторий** и откройте в VS Code с PlatformIO
2. **Установите серийный номер устройства** в `include/DeviceConfig.h`:
   ```c
   #define DEVICE_SN "MOJ_UNIKALNYJ_SN"
   ```
   Этот SN используется как MQTT Client ID, пароль веб-интерфейса по умолчанию и идентификатор в MQTT топиках.  
   *Можно изменить через Serial командой `PROVISIONSN` (см. раздел восстановления).*

3. **Укажите ваш MQTT брокер** в `include/MqttConfig.h`:
   ```c
   #define DEFAULT_MQTT_BROKER_HOST "vash-broker.example.com"
   #define DEFAULT_MQTT_BROKER_PORT 8883
   #define DEFAULT_MQTT_PASSWORD "vash_parol"
   ```
   *Позже можно изменить на странице **MQTT Settings** веб-интерфейса.*

4. **Укажите ваш M-Bus шлюз** в `include/DeviceConfig.h`:
   ```c
   #define DEFAULT_MBUS_GATEWAY_HOST "192.168.1.100"
   #define DEFAULT_MBUS_GATEWAY_PORT 1001
   ```
   *Позже можно изменить на странице **M-Bus Gateway** веб-интерфейса.*

5. Соберите и залейте прошивку:
   ```bash
   pio run -e wt32-eth01-dev -t upload
   ```

## ⚠️ Важно: Серийный номер и первая прошивка

### Как работает серийный номер

Серийный номер (SN) хранится **в NVS (энергонезависимой памяти)** платы. При первой загрузке после прошивки:

1. Прошивка проверяет, есть ли SN в NVS
2. Если SN в NVS **отсутствует** — он автоматически записывается из `DEVICE_SN` (значение, указанное в `DeviceConfig.h` при сборке)
3. Если SN в NVS **уже есть** — используется сохранённый, а значение из `DEVICE_SN` игнорируется

**Это означает, что при последующих перепрошивках с тем же или другим `DEVICE_SN` — SN в NVS не изменится!** NVS не стирается при обычной загрузке через USB.

> **🔑 Пароль от веб-интерфейса** — по умолчанию равен тому же серийному номеру, который был записан в NVS при первой загрузке. Если вы не меняли SN через `PROVISIONSN` — пароль = `DEVICE_SN` из прошивки. Если меняли — пароль = новый SN.

### Как изменить серийный номер на уже работающей плате

Существует **два способа**:

#### Способ 1: Через Serial (рекомендуется, dev-профиль)

При каждой загрузке в dev-режиме плата выводит в Serial:

```
Type RESETWEB in Serial within 5 seconds to reset web credentials.
Saved device serial in NVS: SN1234
Type PROVISIONSN in Serial within 5 seconds to overwrite NVS serial with build DEVICE_SN: SN1234
```

У вас есть **5 секунд** после появления этого сообщения, чтобы отправить одну из команд:

| Команда | Действие |
|---------|----------|
| `RESETWEB` | Сбрасывает учётные данные веб-интерфейса на `admin` / текущий серийный номер |
| `PROVISIONSN` | **Перезаписывает** SN в NVS значением из `DEVICE_SN`, указанным при сборке прошивки |

**Пример смены SN:**
1. Меняете `#define DEVICE_SN "MOJ_NOVYJ_SN"` в `DeviceConfig.h`
2. Перепрошиваете плату
3. При старте в течение 5 секунд отправляете `PROVISIONSN` через Serial
4. Плата подтверждает: `Device serial stored in NVS: MOJ_NOVYJ_SN`

#### Способ 2: Сброс NVS (GPIO режим)

Если вы используете **prod-профиль** (или не успели отправить команду):
1. Замкните **GPIO12** на **GND**
2. Подайте питание на плату
3. NVS будет полностью стёрта
4. **Уберите перемычку** и перезагрузите плату
5. При старте SN будет записан из `DEVICE_SN` заново

> **Внимание:** GPIO-сброс удаляет **все** настройки (MQTT, сеть, M-Bus устройства, пароль веб-интерфейса), а не только SN.

## Сброс к заводским настройкам (GPIO, production режим)

**Зажмите GPIO12 на GND** при подаче питания, чтобы полностью стереть NVS.

После сброса:
- Все настройки вернутся к значениям по умолчанию (из `DeviceConfig.h` и `MqttConfig.h`)
- Серийный номер будет заново записан из `DEVICE_SN`
- **Удалите перемычку** перед следующей перезагрузкой, иначе NVS будет стёрт снова

## Автоматическая отправка телеметрии (Auto Refresh)

> **Важно:** Публикация данных в MQTT происходит **только** при включённом автоматическом обновлении. Ручное нажатие **Refresh Now** на веб-интерфейсе обновляет кэш на плате, но **не отправляет** данные в MQTT.

Если установлен интервал автоматического обновления (не равен `0`), прошивка самостоятельно опрашивает сохранённые M-Bus устройства и публикует телеметрию в MQTT.

### Как настроить

1. Добавьте M-Bus устройства через веб-интерфейс (страница **M-Bus Devices**)
2. Для каждого устройства откройте страницу просмотра телеметрии (`/mbus-device`) и **отметьте галочками поля**, которые должны попадать в телеметрию — в MQTT будут публиковаться только выбранные поля
3. На главной странице (**Main**) укажите интервал автообновления в минутах в поле **Auto (min)**
4. Нажмите **Save**

> Если интервал = `0` — автообновление отключено, публикации в MQTT не будет.

### Когда происходит автообновление

- Если время **синхронизировано (SNTP)** — автоопрос выполняется в начале каждого временного слота, кратного заданному интервалу (например, при интервале 60 мин — в :00 каждого часа, при 15 мин — в :00, :15, :30, :45). Это гарантирует, что все устройства опрашиваются в один и тот же момент времени
- Если время **ещё не синхронизировано** — первый опрос выполняется через указанный интервал после загрузки, затем по таймеру
- После успешного автоопроса прошивка публикует JSON телеметрию в MQTT
- Логи ошибок также публикуются только при автообновлении

> **Ограничение:** Максимум **50 устройств** за один цикл автообновления.

## MQTT Топики

Во всех топиках `%s` заменяется на серийный номер устройства.

| Топик | Направление | Описание |
|-------|-------------|----------|
| `telemetry/%s` | Публикация | JSON телеметрия с показаниями выбранных полей (только при автообновлении) |
| `telemetry/%s/log` | Публикация | Логи (предупреждения, ошибки) от устройства (только при автообновлении) |
| `config/%s` | Подписка | Команды конфигурации |

Топики можно переопределить через веб-интерфейс (страница MQTT Settings).
